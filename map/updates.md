# Map Updates

Record changes as small, auditable entries. Every update should include the date, source, route status, and whether the destination is public and permissioned.

## Update protocol

1. Check the official destination first.
2. Prefer documented APIs, RSS/Atom, JSON feeds, public export, or accessible HTML.
3. Test the route without defeating a challenge, login wall, paywall, rate limit, or access control.
4. Mark the route `verified`, `stale`, `blocked`, or `retired`.
5. Add a replacement only when its terms and provenance are clear.
